# 首批实施计划：只读方案与证据浏览

日期：2026-09-30。代码基线为本目录新建工程；不接续此前本地测试代码。

## 已完成情况

现有 PostgreSQL `chemo_regimen_catalog` 已有方案库 9 表、证据库 6 表和业务运行 35 表。方案 188 套，方案版本 188 条；证据记录 153 条、关联 113 条。当前版本与证据均为 `DRAFT`。这些是数据库现状，不等于产品读接口、临床匹配、Agent、医院接口或医生确认已实现。

## 模块分工

| 模块 | 首批输入与输出 | 首批职责 |
|---|---|---|
| 后端只读 API | 方案编码/版本 ID → 列表、固定版本详情、关联证据 | 参数校验、分页、确定来源状态；仅本地测试模式开放，无写操作 |
| 前端方案浏览页 | 只读 API → 目录主从视图与证据侧栏 | 统一设计体系、状态展示、键盘与窄窗适配；查看不等于采用 |
| 数据库 | 现有 `regimen_catalog`/`knowledge` → 固定版本查询 | 不建新表、不回填、不发布草稿；业务运行 35 表保持空表 |
| Agent 与 Reviewer | 后续批次 | 定义边界：文本理解、受控工具编排、解释、影子复核；不参与首批真实运行 |

## 批次与验收

1. **本批**：方案列表、固定版本详情、证据列表与原文定位，建立视觉设计体系；自动测试、实际联调和浏览器截图。该页面不是患者工作台。
2. 患者标准化与 `AUTO_PREPARE`：纯合成测试患者、明确标记的医院模拟适配器、持久化上下文/任务/快照；旧患者响应不能覆盖新页面。
3. 阶段 0：确定性匹配、V2.2 区域/等级/提示分离、受控计算与对比；无审核证据不进入临床推荐。
4. Agent 与 Reviewer：Claude Agent SDK 适配层、只读 MCP 工具、结构化输出与独立影子复核；无模型配置时显示未接入。
5. 患者方案编辑：固定模板实例、不可变修订、保存/确认与并发冲突；医院写回另行联调。

## 首批页面方向

采用“临床编辑台”视觉：暖白底、深青墨色、细线分隔和克制的琥珀提示。首批仅为方案与证据浏览页；真正的患者工作台将围绕当前患者、就诊、候选、复核和医生决策建设。当前尚无医院上下文，页面明确显示“未接入”，不填造患者。桌面端压缩顶部信息，左侧列表独立滚动，右侧详情与患者状态保持固定；长证据在右侧抽屉按需打开。草稿/未核验用文字、图标和形状同时表达，不用颜色单独承载状态。

`查看详情`、`加入对比`、`采用方案`、`保存`、`确认`具有不同语义。本批仅开放查看；其他动作显示未来能力状态，不产生数据库写入。

## 首批接口合同

- `GET /api/v1/status`：数据库与模型/医院能力状态，明确 `READ_ONLY_TEST`。
- `GET /api/v1/regimens?search=&page=&page_size=`：分页列表，保留方案及固定版本 ID、状态和证据数量。
- `GET /api/v1/regimens/{regimen_id}/versions/{version_id}`：固定版本详情、药品组成和内容摘要。
- `GET /api/v1/regimens/{regimen_id}/versions/{version_id}/evidence`：该版本的证据关联及来源/审核状态。
- `GET /api/v1/evidence/{evidence_id}`：原文、来源位置、原生等级及项目等级；不存在时返回 404。

首批无写接口。生产环境没有可信认证适配前拒绝开放这些路由。分页有上限；请求失败与无结果分别返回。
