# 临床入口与测试上下文读取：本批验收

本批只修正入口和只读合同，**没有完成 `AUTO_PREPARE`、候选生成或患者方案保存**。

## 已实现

- `/` 默认进入临床页；`/catalog` 独立浏览公共方案。临床页没有 `context_id` 时不显示公共方案为患者候选，也不提供未绑定患者的编辑预览。
- `GET /api/v1/contexts/{context_id}` 从显式配置的独立运行测试库读取既有 `launch_context`、`prepare_run`、固定 `decision_run` 和候选；不创建记录。仅允许本机/测试环境，测试库名必须包含 `test` 且不得与目录库 DSN 相同；查询进一步限定 TEST_ONLY 医院及 `SYNTH_` 患者/就诊标识。生产环境拒绝把 `context_id` 当认证。
- 页面区分无上下文、读取失败、已失效、准备中、准备失败、决策失败、本次无候选和已有测试候选。轮询只在本次任务仍运行时进行；URL 中的上下文变化被前端接收后，会卸载旧视图、取消旧请求并清除旧内容。宿主切换患者的事件接入仍待下一批验证。
- 候选读取只取同一上下文、准备任务和快照的决策运行，展示数据库保存的顺序和推荐/X 区，不按标签重新排序。没有已保存的候选时不临时拼接目录方案。

## 验证

- `backend`: `uv run ruff check .` 通过；`uv run pytest -q` 为 5 通过、1 跳过。API 测试覆盖测试上下文读取、未知上下文 404，以及生产环境拒绝凭 `context_id` 读取。
- 对独立 `chemo_runtime_schema_test_20260930` 数据库只读执行候选 SQL 的 `EXPLAIN`，语法与现有 T13/T14 结构匹配；没有插入患者或候选。
- `frontend`: `npm run build` 通过。无头 Chromium 实际打开本地服务，核验默认临床页、`/catalog` 导航、未知上下文错误，以及返回临床页不保留旧错误。另以浏览器网络拦截提供明确标识的**合成合同返回**，验证候选可显示，且同页换 `context_id` 后旧患者和旧候选立即消失；这不是数据库生成候选的证明。截图：[无上下文](../../screenshots/患者工作台-无上下文.png)、[窄窗口](../../screenshots/患者工作台-窄窗口.png)、[独立目录](../../screenshots/独立方案库浏览.png)、[未知测试上下文](../../screenshots/测试上下文未找到.png)。
- 本地服务实测：目录接口 200；未命中的测试上下文返回 `CONTEXT_NOT_FOUND` 404。独立测试库暂无合成上下文，因此**未验收到有候选的页面，也未验收到患者切换时旧请求与新请求交错的真实运行**。
