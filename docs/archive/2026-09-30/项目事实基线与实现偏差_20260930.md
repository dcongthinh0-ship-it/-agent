## 已确认的医生主流程

1. 医生在院内工作站进入或切换患者。宿主传当前患者、就诊、操作者和科室上下文；后端在医生点开智能体之前持久化 `context_id`、执行 `AUTO_PREPARE`，读取受授权数据、冻结快照并生成该次候选。准备中、失败、过期要如实显示。
2. 医生点击工作站右下角的智能体悬浮挂件。宿主以本次 `launch_url` 打开页面；前端凭 `context_id` 查询已有准备状态与候选。`context_id` 是关联标识，不是认证凭据。切患者要立即清掉旧页面主体并拒绝旧请求的迟到响应。
3. 临床首屏显示当前患者、就诊、准备状态、该患者本次候选与依据。候选来自固定运行和版本，不是公共方案库的 188 条列表。查看、加入对比、选为患者方案是不同动作。
4. 医生明确选定候选后，以确切 `regimen_version_id` 的完整长 JSON 蓝图创建本次患者方案实例。查看和编辑使用同一完整表单布局；病人值、模板原值、计算值、医生修改值与来源分别保存/展示。医生只能修改已审核配置允许的字段。保存生成不可变修订，确认锁定确切修订和内容哈希；确认后的修改另成新修订。公共模板不被医生修改。
5. 主 Agent 处理必要的自由文本理解、受控工具编排、知识检索和解释；独立 Reviewer 核验引用、规则和医生修改。规则门禁、证据等级、剂量计算、权限、数据库写入及院方交付由受控程序承担。Agent、Reviewer 和院方服务目前均不能因设计文件存在而标成已接通。

公共方案库浏览、证据维护和运行管理是独立授权入口。9 月 30 日计划中“先只读浏览、后患者准备”是**开发顺序**，不改变上述最终临床流程。V2.2 只有 X 改变展示区域；分期、线次、缺失数据及普通风险提示不能擅自降级、排除或重排。旧 A/B/H/P/X 互斥分类已过时。

## 必须纠正的实现偏差

1. **入口错位。** 当前 `App.tsx` 默认 `catalog`，把目录与工作台并列成手动切换导航；这不能代表院内“患者预准备后点挂件即见候选”的临床入口。目录应保留为独立的受权浏览功能，不能用其列表充当患者候选。
2. **编辑归属错位。** 当前 `PatientEditor.tsx` 只修改浏览器内存中的预览值，没有患者实例、快照绑定、版本/修订号、保存/确认。其 UI 不能标为医生已可编辑患者方案。
3. **控件锚点与权限未核实。** 当前蓝图渲染依赖标签文本、`item_key`、行号和药名推断输入位置，需对 188 份蓝图做逐项锚点核验。旧 7 月生产参数文件曾只准一期编辑主治疗“实际使用剂量”，而历史 PoC 演示过更广字段；9 月计划要求编辑范围取已审核配置。现预览开放剂量、途径、频次和日期，不可直接作为正式权限白名单。
4. **状态与临床资格。** 全部版本、证据仍 DRAFT。未命中/未关联不能解释为临床不适用，草稿候选不能默认显示为可采用或已通过；测试隔离状态要和真实生产准入分开。
5. **院方接口只到需求文档。** 最新接口修订版的示例 Method/Path、轮询、认证、编码映射、挂件承载方式与尺寸均待院方确认。早期 WinDHP/Meehealth/华润材料仅是参考，不能填成温州医院正式协议。模拟适配器必须显式标记为测试。
