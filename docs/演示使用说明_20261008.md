# 10月8日患者流程演示

入口：<http://127.0.0.1:8012/demo/host>。请使用这个工作站入口，患者身份由工作站传入挂件。

启动：双击项目根目录的 `启动演示.command`，等待终端显示“演示已启动”。Docker Desktop 及本项目 PostgreSQL 容器需处于运行状态。脚本会准备本项目依赖，使用后端8012、前端5174；已运行时复用演示服务，遇到其他服务占用端口会停止启动并提示。

## 建议演示顺序（约8分钟）

1. 选择“演示患者甲”，等待右下角“候选已就绪”，打开挂件并点“展开”。进入患者时已经自动准备，打开挂件不重新准备。
2. 选 BC-001，查看方案组成及原文依据。勾选两份候选可对比；对比和查看不会选用方案。
3. 点击“选用并编辑本次方案”，在同一张原表单查看患者回填、原文治疗、支持治疗及风险说明。
4. 点击“填入本例演示值”。此按钮只为 BC-001 提供虚构的周期、日期及四条药品填写值。可以收起再打开，检查未保存内容仍保留。
5. 点击“保存本次修订”。保存后“确认本次方案”才可用；逐项核对测试提示后确认。改动已保存方案时填写修改原因，并重新保存、确认。
6. 查看“修订记录”，可以打开不可变历史表单。确认同时请求独立复核；当前模型未配置，会明确显示未执行。
7. 在“院方交付检查”依次点“模拟预校验→模拟导入医嘱→回查医嘱结果→模拟病历归档→回查模拟签名”。导入先显示“已受理”；回查后才显示全部处理成功。归档与签名是两个不同状态。
8. 收起后切换患者丙，查看缺体重、缺ANC及过期检验提示，候选仍可浏览。切患者丁，选择BC-001并重复保存、确认、预校验、导入、回查：第二条医嘱显示模拟缺货，不能归档，可点击“撤销模拟交付”。

## 重复演示和恢复

- “新一轮演示（保留之前记录）”生成新的演示就诊号，可以从头开始，不删除之前的修订或医院回执。
- 关闭或重启服务不清空数据。切回同一患者、同一就诊时，可在“本次就诊已选方案”读取已保存历史；新患者快照下旧方案显示只读，可重新选用。
- 重复点击导入、撤销或归档，复用该修订的幂等操作标识。同一修订不会新建第二批医嘱。
- 刷新工作站或切换患者会重新取得有效的演示身份，服务跨天运行也可以继续演示。不要沿用停留超过24小时的旧页面。
- 不需要清空数据库。建议正式演示前点一次“新一轮演示”，确保从未提交状态开始。
- 启动脚本终端关闭时仅停止该脚本启动的服务；之前已启动的服务继续运行。日志在项目 `artifacts/demo-20261008/backend.log` 和 `frontend.log`。

## 当前能力边界

方案原文来自现有188份表单，证据关联113条已修复指纹兼容，仍保留原审核状态。按癌种生成的测试候选及证据等级不等于临床已放行的推荐。

医院模拟按 `温州化疗智能体项目接口文档v1.0.1-三医管理字段补充修订-李洪康.docx`：8个读取接口、6个交付接口。调用通过项目实际HTTP适配器及严格合同校验，医院侧回执持久化。当前交付演示明确只配置BC-001四条主治疗药；其他方案及预处理、水化、支持治疗的通用医嘱编译和院内正式映射还未完成。

主Agent、Reviewer沿用真实模型接入实现。当前密钥、模型和启用配置为空，不伪造模型解读或复核成功。若需要演示真实AI，应由用户在本项目 `backend/.env` 填入自己的模型配置后重启服务；医院模拟不提供假模型输出。

体表面积参考计算使用明确标识的演示配置；区间或阶段剂量不自动推成临床实际剂量。演示填写值及虚构数量仅用于展示保存和接口流程。
