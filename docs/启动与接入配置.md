# 启动与接入配置

## 本地服务

正式工程目录为 `14_化疗智能体产品`，使用原有数据库容器及 `chemo_regimen_catalog` 数据库。`backend/.env` 是被 Git 忽略的本地配置；`.env.example` 是空值模板，不可填入其他项目密钥。后端 8011，前端 5173，Vite 的 `/api` 代理指向 8011。独立 worktree 联调可通过 `CHEMO_API_ORIGIN` 指定其他 API 端口。

后端启动时会启动持久化 Worker；不会自动改表、导入患者或发布知识。增量迁移需要非空备份文件、明确目标库，并验证已执行脚本的校验和：

```sh
uv run python -m chemo_agent_product.migrate --env-file .env --target-database chemo_regimen_catalog --backup-file /明确的本地备份路径.dump
```

迁移记录在 `ops.product_migration`。已执行 SQL 不得改写；需要新迁移修正。原 9+6+35 表和正式资料是前置条件。代码回退用阶段提交的 `git revert`；不要重置或删除已经存在的业务历史。

## 模型密钥预留

以下位置已保留在 `backend/.env.example` 和本地 `.env` 的后端配置中：

| 环境变量 | 用途 |
|---|---|
| CHEMO_PRODUCT_MODEL_ENABLED | 当前 false；明确启用后才调用 |
| CHEMO_PRODUCT_MODEL_API_KEY | 用户自己的模型服务密钥，当前为空 |
| CHEMO_PRODUCT_MODEL_BASE_URL | 可选的 Anthropic Messages 兼容服务地址，当前为空 |
| CHEMO_PRODUCT_MODEL_NAME | 主 Agent 模型名称，当前为空 |
| CHEMO_PRODUCT_REVIEWER_MODEL_NAME | 独立 Reviewer 模型名称，未指定时复用主模型名称 |
| CHEMO_PRODUCT_MODEL_TIMEOUT_SECONDS | 单次执行时间上限 |
| CHEMO_PRODUCT_MODEL_MAX_TURNS | 工具编排轮数上限 |
| CHEMO_PRODUCT_MODEL_MAX_BUDGET_USD | SDK 单次预算上限；兼容平台的计费需另核实 |

Claude Agent SDK 使用 Anthropic 协议。OpenAI Chat Completions 地址不能直接作为这里的 Base URL。当前锁定 SDK 0.2.164；启动时需有其官方 Claude Code CLI 运行依赖。项目隔离工作目录、配置来源和认证环境，不借用其他项目的 OAuth 或云服务凭据。填好后重启服务，并实际检查工具调用、引用、超时和成本；测试替身通过不等于真实模型已接通。

主 Agent 提示词为 `recommendation.v1.md`，Reviewer 为 `reviewer.v1.md`，随包分发。模型只能使用患者快照、候选、固定方案、证据、规则、计算、修订和知识检索八个读取工具。文本提取保留原文字符位置、否定和不确定状态，不自动转成已确认事实；页面不展示模型私有思维链。

## 挂件与可信工作站

宿主页加载前端 `chemo-widget.js`，通过 `createChemoWidget({serviceOrigin, getAccessToken, onError})` 创建挂件。`getAccessToken` 从院内受信后端取得凭据；不要在网页源码写密钥。

患者进入或变化时调用 `widget.updatePatient`，传入最终接口文档要求的患者、就诊、操作人员和科室上下文。挂件固定请求 AUTO_PREPARE，维护会话与递增代次，关闭时也会读取准备状态。打开只加载已有 context；患者变化先卸载旧页面、清除内存凭据，再发起新准备。

iframe 与宿主通过 CHEMO_READY / CHEMO_CONTEXT 交换上下文，严格核验源窗口及 origin。凭据只存在内存，不进入 URL 或 localStorage。后端同时验证医院、人员角色、患者及就诊归属、TTL、幂等键与代次。仅凭一个 context_id 不能取得患者数据。

本地/测试身份使用服务端签名合同，签名 Key 至少 32 字符；这不是生产 SSO。生产医院身份、签发方、令牌校验与角色映射仍需院方确认，本期 production 明确拒绝使用本地测试凭据。院内医院、人员和科室编码必须来自真实配置，不能使用空值绕过。

## 医院适配

读取模板在 `backend/config/hospital-read.example.json`，交付模板在 `hospital-delivery.example.json`，所有 URL 和医院编码为空。用经院方确认的本地文件配置以下变量：

- CHEMO_PRODUCT_HOSPITAL_ADAPTER_CONFIG：八个只读操作、患者/就诊定位、事实字段、单位、状态、时间、文本记录和分页规则。
- CHEMO_PRODUCT_HOSPITAL_DELIVERY_CONFIG：六个交付/回查合同的路由。设置此文件不代表获得临床提交权限。
- CHEMO_PRODUCT_HOSPITAL_AUTHORIZATION：由配置中的凭据引用读取，不能写进 JSON 或 Git。
- CHEMO_PRODUCT_TRUSTED_HOST_ORIGINS：可信宿主 origin 清单，不能为了方便接受任意网站。

最终 v1.0.1 第 4.1 节是交付字段合同基线。部分示例少了必填数量/单位/版本/D1 起始时间，不能据此省略。主管、主治、副主任和主任医师分别保留；签名查询采用正文枚举，不把示例 AVAILABLE 当 SIGNED。

读取调用保存真实请求哈希、结果哈希、状态、时间及传输结果，认证头不入库。交付驱动解析预校验、导入、状态回查、撤销、归档及签名回查；超时结果未知，不能自动重发新批次；部分成功不当作全部成功。驱动尚未开放生产写入口，前端当前展示本地交付缺项检查，不冒充院方预校验。

## 仍需真实配置或联通验收

院方 SSO 与授权、医院读取/写入 URL、患者与就诊字段映射、疾病与病理字典、药品/途径/频次/数量单位/执行科室、三医人员和签名流程、已审核适用关系与规则来源、完整表单必填项、处方与全部支持治疗医嘱的结构化编译，以及真实模型调用。当前编辑可修改治疗安排、主治疗药实际剂量/治疗日/备注；新增删除药物、任意改单元格和全类别医嘱开立未开放，不能声称已完成全部院内医嘱编辑。

FDA5、CSCO7、I-A 为已有证据映射配置，原始推荐等级仍保留。未审核知识不会自动成为临床已批准，测试候选与临床已核验结果区分显示。普通缺值、风险提示、分期和线次不改变等级；只有明确配置的 X 理由影响展示区域。

## 验证命令

后端：`uv run ruff check src tests`、`uv run pytest -q`。完整数据库测试需将 `CHEMO_WORKFLOW_TEST_DSN` 与 `CHEMO_TEST_DATABASE_URL` 明确指向隔离测试库；未配置时会跳过对应测试，不能把跳过说成通过。前端：`npm test`、`npm run build`。

一次性浏览器验收脚本在 `backend/tests/browser_acceptance_harness.py`，只允许显式命名含 test 的隔离库，在外层回滚事务中挂接真实 API、Worker 和挂件。脚本内读取测试替身不会访问真实医院，模型保持关闭，结束时核对临时医院数据为零。它是开发验收工具，不是生产模拟接口，也不是此次尚未制作的演示数据集。
