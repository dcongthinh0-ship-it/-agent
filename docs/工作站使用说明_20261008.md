## 操作顺序

1. 选择林雅琴，等待右下角“候选已就绪”，打开并展开工作台。
2. 在“本次诊疗”查看患者候选、数据提示和方案依据；右上角“智能体解读”查看后台模型进度与结果，可输入补充核对问题。比较后选用 BC-001。
3. 点击“填入预设值”，核对周期、治疗日期、各药实际剂量和给药安排，保存本次修订。
4. 单独确认本次方案，逐项核对提示。确认只记录当前修订，医嘱需单独提交。
5. 在“院方交付检查”依次操作“医嘱预校验 → 导入医嘱 → 回查医嘱结果 → 病历归档 → 查询签名回执”。
6. 切换王丽芳查看资料缺失／过期，再切周晓梅查看库存不足、禁止归档及“撤销本批次”。

“开始新的就诊记录”保留此前已保存内容和回执，可重新走流程。收起再打开不会丢失尚未保存的填写内容。

## 当前能力与隔离

这些姓名及资料均为新制作的样例，所有操作在独立工作目录、独立样例数据库及本地接口验证环境运行。代码修改不合并到真实产品分支；配置、回执、测试报告与截图也保存在这个独立目录。

目前按癌种形成候选并核对数据有效性，完整个性化适用规则仍待配置。依据保留真实审核状态。BC-001交付只包含四条主要治疗医嘱；预处理、水化、支持治疗及其他方案的通用医嘱映射仍待完成。

本独立版本已配置海南模型，通过项目外的本机转接服务调用。模型配置保存在本目录被 Git 忽略的 `artifacts/demo-20261008/model-settings.json`，启动脚本只接受模型变量，不能用此文件覆盖数据库或身份配置；正式产品 `.env` 不受影响。先启动独立转接服务，再使用本目录启动入口。患者准备完成后自动启动解读；已保存修订可请求独立复核，确认后也会排队复核。结果必须通过来源引用校验，失败时保留真实失败状态。本地签名回执仍仅验证模拟接口流程。

2026-10-10 联调修复了 SDK 最终结构化结果被权限钩子误拦的问题，并给八个只读工具设置了 300,000 字符的内联结果上限，覆盖当前约 76,000 字符的 39 份候选列表和最大约 218,000 字符的单份模板，避免转存为 Agent 无权读取的文件。方案查询保留完整正文、药物、字段、数据核对提示和原始版本引用，省去重复的 Word 排版几何信息；医生页面仍使用原完整模板。摘要来源引用在输出 Schema 中必填且非空，主 Agent 和 Reviewer 提示词也明确要求准确复制固定引用。文件、Shell 和写入工具仍被禁用。使用 Claude Agent SDK 0.2.164 的 `ToolAnnotations`，其上限通过工具 `_meta` 传递，行为依据 [官方 MCP 输出限制说明](https://code.claude.com/docs/en/mcp#raise-the-limit-for-a-specific-tool)（核对日期：2026-10-10）。本轮 103 项后端测试通过，包括独立数据库流程、权限边界、方案及修订引用、摘要来源约束和启动配置隔离。

旧页面提示“身份凭据无效或已过期”时，刷新整个工作站页面重新获取当前凭据，再选择患者；不需要修改密钥或清空数据库。首次解读需等待模型完成，侧栏逐项显示已读取的资料与真实运行状态。本机模型任务超时目前为 600 秒；共享模型服务排队可能影响耗时，超过上限会显示真实失败代码，可重新请求。
