# 智能体 · 化疗患者工作台

本工程独立新建，包含 `backend/` 与 `frontend/`，不延续旧测试代码。代码边界和用户已确认规则见 [AGENTS.md](AGENTS.md)。

主流程：院内工作站进入或切换患者 → 右下角挂件静默 AUTO_PREPARE → 后端读取、保存快照并生成候选 → 医生打开已有结果 → 查看或对比 → 选用一份 → 在完整 Word 形式表单内回填、编辑 → 保存不可变修订 → 单独确认。`/` 是患者工作台，`/catalog` 是公共方案与证据浏览，查看不会生成患者方案。

主 Agent 使用 Claude Agent SDK 适配器，通过八个只读 MCP 工具读取本次资料，生成带固定引用的解释及待核对文本事实。独立 Reviewer 针对已保存的确切修订提出发现，不改写方案或签发临床放行。规则、排序、计算、写库及确认由业务程序控制。提示词在 `backend/src/chemo_agent_product/prompts/`。

真实院方服务和生产身份尚未接入。本独立工作站通过私有本地配置启用海南模型，患者资料和医院接口仍使用样例环境；不能直接用于真实诊疗。模型运行和页面结果分别验收，操作入口见 [医生工作站使用说明](docs/工作站使用说明_20261008.md)。历史功能与测试见 [本轮验收记录](docs/验收记录_20261007.md)，原有配置说明见 [接入说明](docs/启动与接入配置.md)。

本独立工作站使用现有 `chemo-regimen-catalog-db` 容器内的样例库 `chemo_demo_test_20261008`，方案、证据和业务运行 schema 均在该样例库中。正式产品的 `chemo_regimen_catalog` 不接收工作站患者操作。本工程迁移是在现有 9+6+35 表基础上的增量迁移，不负责从空库重新导入院方方案资料。自动化测试使用另一独立库 `chemo_product_test_20261007`，临时患者关系均回滚；不提交数据库备份、密钥或患者资料。

启动后端（`backend/`）：

```sh
uv sync --extra dev
uv run uvicorn chemo_agent_product.api:app --host 127.0.0.1 --port 8011
```

启动前端（`frontend/`）：

```sh
npm ci
npm run dev
```

打开 `http://127.0.0.1:5173/`。独立打开时没有患者上下文，应显示等待工作站；可从“浏览”查看真实方案库。
